# Communication Engineering project charter

## Purpose

Define the practical problem this project will solve. Do not assume that
“Communication Engineering” already names a distinct discipline; that is a research
question, not a starting fact.

## Intended users

Initial candidate: people following multi-step technical instructions. The
specific user group remains to be selected and validated before the first
experiment.

## First bounded outcome

Proposed: compare two variants of a synthetic procedural document for a
specified audience and measure unassisted task completion, critical errors,
time, assistance, comprehension, and satisfaction. See `RP-COMM-2026-0001`
and proposed mission `MS-COMM-2026-0001`. This remains subject to review.

## Included

- Definition of the first user and communication problem.
- A working vertical slice.
- Evidence and decision traceability.
- Evaluation of the Repository Operating System pilot.

## Excluded

- Broad discipline claims without comparative evidence.
- An exhaustive communication taxonomy.
- Autonomous acceptance of research or policy.
- Production handling of secrets or sensitive communication data before a
  privacy and threat review.

## Success criteria

- The first vertical slice has observable acceptance tests.
- Material decisions cite their evidence and alternatives.
- A successor can continue from repository records without chat history.
- Pilot measurements can compare the operating approach with a declared
  lightweight baseline.

## Constraints and assumptions

- Use synthetic, non-sensitive tasks for the first experiment.
- Treat accessibility, truthfulness, and safety as constraints, not optional
  optimization targets.
- Do not infer comprehension from preference or readability alone.
- Assumption: a bounded procedural problem can test the operating model
  without first resolving the full disciplinary boundary.

## Owners and decision authority

Not yet assigned.
